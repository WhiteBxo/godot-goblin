# Day 1 · Scene 01：第一位顾客

## 编排约定

- **宿主场景：** 由 Codex 检查实际场景，优先复用现有奶茶店场景。
- **开始条件：** 第一天开始营业。
- **重复规则：** 正式剧情只触发一次。
- **创作要求：** 保留原始对白，不擅自增加剧情事件。

## Beat opening

**执行模式：** 自动演出

**演出：**
- 主角站在柜台旁。
- 主角看着空荡荡的店铺，叹一口气。

**对白：**

主角：“今天又一个客人都没有……”

主角：“再这样下去，下个月房租怎么办？”

**结束条件：**
- 对白结束。
- 设置阶段 `day1.before_order`。
- 当前自动演出结束，恢复玩家操作。

## Beat check_order

**执行模式：** 玩家操作

**玩家目标：**
- 玩家自由移动。
- 前往订单板，按 E 查看订单。

**触发方式：** 使用现有交互点 `orders`。

**完成条件：**
- 订单板交互成功。
- 触发 `day1.order_tutorial` 事件。

**失败处理：**
- 如果交互不满足剧情条件，保留原有订单板 UI 行为。
- 不得因玩家靠近订单板就自动触发剧情。

## Beat order_tutorial

**执行模式：** 自动演出

**触发条件：** 玩家成功调查订单板。

**对白：**

主角：“第一单来了，赶紧做完，争取留住这个客人！”

**结束条件：**
- 对白结束。
- 设置阶段 `day1.waiting_order`。
- 结束当前演出，恢复玩家操作。

## Beat make_and_deliver

**执行模式：** 玩家操作

**玩法目标：**
- 玩家亲自查看当前订单。
- 前往制作台，选择正确原料并提交。
- 完成当前订单的实际交付。

**玩法完成条件：**
- 必须由真实奶茶订单系统确认交付成功。
- 制作失败、库存不足、仅打开或关闭 UI 均不算完成。
- 当前阶段的订单交付结果成为剧情可读取的状态。

**历史结果处理：**
- 如果本剧情要求的订单此前已经成功交付，则不要求玩家重复制作。
- 如果目标是必须在本阶段新完成的操作，则必须明确要求新的成功结果。

**完成后：**
- 等待制作 UI 关闭。
- 等待暂停状态解除。
- 自动触发后续剧情。

## Beat customer_reaction

**执行模式：** 自动演出

**触发条件：** 订单实际交付成功，且前置教学事件已经完成。

**演出：**
- 镜头聚焦顾客。
- 顾客看向奶茶，露出惊讶的表情。

**对白：**

顾客：“没想到还挺快的。”

主角：“那当然，专业的！”

**结束条件：**
- 对白结束。
- 标记本次剧情完成。
- 镜头恢复正常跟随。
- 玩家重新获得控制权。

## 玩法与剧情约束

- 玩家操作期间允许正常移动、交互和使用制作 UI。
- 顾客在不同阶段之间必须保留正确的位置和状态。
- BGM 可以跨越自动演出与玩家操作阶段持续播放。
- 不得使用固定等待时间代替真实的玩法完成条件。
- 缺少真实业务状态或触发能力时，列出待实现事项，不得伪造完成标记。

## 验收标准

- 玩家能够亲自完成订单。
- 错误配方不能触发顾客反应。
- 成功交付后自动进入后续演出。
- UI 未关闭时不会抢先播放对白。
- 剧情结束后，玩家可以正常移动和交互。
