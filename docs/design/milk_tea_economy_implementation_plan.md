## 数据设计

静态配置建议增加 `src/resources/milk_tea/economy_rules.gd/.tres`，统一人类 3G、经营 T1–T5 的标准价/五次/加价区间、爆品 150G。战斗另建定义和价格配置，使用独立 `combat_tier`，不复用经营枚举。现有菜单引用同一规则资源。

`IngredientDefinition` 增加经营等级及 `item_scope` 等效字段（经营 / 任务专用 / 非经营）；F09 保留 `free_recipe_allowed = false` 与空市场价，同时标为任务专用。任务报价 200G/份存任务规则，不向 `products` 自动生成 F09 商品。用途限制在查询与提交两层执行，不能只在 UI 隐藏。

人类成品用稳定 H 映射，配方配置增加类别及固定价；解锁复用已有事实查询，避免在 Resource 内保存运行进度。旧 `price`、标准 `market_price`、商店实际 `unit_price`、成品售价为四个明确字段，不相互回填。免费获得只影响实际采购支出。

爆品配置改为 `{id, name, ingredients, first_discovery_reward}`，不再接受售价覆盖；正式 `signatures` 在资料补全前保持空。旧配置格式应经明确迁移或报错处理，不能继续默默读取 `price`。

### 配方价格账本

建议在 GameState 的既有经济子快照内增加 `recipe_prices` 和 `signature_rewards`，由现有会话服务持有，可用一个内部 `RecipePricing` 辅助类计算。它们不是新的全局单例。业务库存中只保留配方身份，所有读取方从同一价格账本取价。

每条报价至少保存：`recipe_id`、规范原料槽（ID、同 ID 的出现序号）、`slot_costs`、`slot_markups`、`slot_prices`、`selling_price`、`price_generated`、`pricing_version`。所有已用槽都记录；人类槽成本为 0、加价为 1，空槽不存。奖励账本以稳定 `signature_id` 为键，记录 150G 和领取回执，不以杯库存或加冰变体作为防重键。

价格身份使用现有 `DrinkFormula.key_for(materials, false)`，即基底+排序辅料，保留重复项。加冰杯继续使用现有库存 ID，指向同一价格身份。重复食材按规范顺序分配独立槽号，不能用只含 `ingredient_id → markup` 的字典丢失重复槽，也不能因辅料换序重抽。

## 首次定价与制作事务

建议提供显式“确认配方”操作，首次登记价格后允许制作或批量制作。这是为明确“首次生成价格”的实现决策，不是附件新增的收费项目。

1. `preview_formula()` 保持纯读取。未登记配方返回价格上下限和 `price_generated = false`，已有配方返回固定值；预览不消耗 RNG、不登记、不扣料、不发奖。
2. 新增拟议 `confirm_formula(materials, request_id)`：校验合法基底、最多三槽、至少一项经营哥布林原料、全部用途资格。使用发现过的原料即可登记，库存不足不影响已登记价格，但会阻止后续制作。
3. 在会话提交锁内查账本；已存在就返回旧价。不存在才为规范槽生成整数加价、计算价格并提交新记录和回执。T1/人类槽固定 1G，其余使用经营档位区间；登记不产生图鉴或奖励。
4. `craft_formula()` 读取已登记价，统一准备原料次数、杯库存、图鉴、制作回执，以及首次爆品奖励草稿。未登记返回明确错误供 UI 引导确认，不能在预览中偷偷登记。
5. GameState 通过拟议 `commit_formula_craft()` 或等效内部事务一次提交库存、价格引用、奖励领取、余额及制作回执，成功后再通知。任一校验失败都不消耗原料、不入杯、不发钱、不写奖励领取。金额溢出同样整体失败。

当前 `TeaProduction.craft_formula()` 直接调用库存写入，不能在其 `changed` 回调里追加 `add_money(150)`；否则制作成功而奖励失败、或通知重入时会出现半提交。沿用现有 `prepare_delivery()` / GameState 静默替换与最后通知的模式扩展，不把“先扣料，再加钱，失败补回”作为事务。

单一配方一次做多杯仅领取一次爆品奖励。交易请求 ID 防重与爆品 ID 防重同时存在；失败请求可重试、成功换请求 ID 仍不能重复领奖。配方首次登记成功后，即使后来缺料或取消制作，旧价仍保留，改回旧组合继续用原记录。

### 文件保存时点

登记价格和首发奖励是必须持久化的整局状态。提交后由 SaveCoordinator 在安全边界请求保存，不在同步通知里写文件；实施时为配方确认/制作所在正式阶段补可恢复检查点。非安全阶段禁用新登记操作或等待安全边界后才向用户确认已保存，不能宣称“永久固定”却只留内存。

普通退出/继续、场景重建必须读取原记录。价格保存实际数值及版本，不依赖每次读档从 seed 重抽。明确恢复更早的历史存档属于回退整局；若产品还要求跨回档防刷价，需要额外设计，当前单槽检查点机制不承诺这一点。

## 销售、采购与任务适配

- 经营采购复用 `WalletTransactions.purchase()`，按整份报价入库、每份 5 次；窗口从 `get_product_quote(s)` 读取实际价和余量，不从图鉴猜报价。商店标准价与实际折扣分别配置，当前无需扩展浮点舍入规则。
- 人类固定销售读取成品类别的 3G；哥布林销售读取账本。沿用交付草稿一次扣杯、入钱、写事实/回执，制作与出售均不再次扣原料成本。
- `rewards.money` 目前优先于动态饮品售价。实施时区分销售任务与报酬任务，清理正式销售中残留的 10G/20G 覆盖，保留任务明确报酬及醉酒守卫显式零收入。
- Day 1 现有五单使用教学成品、首单 +10G、其余 strange_coin ×1；直接改 3G 会与 1 枚=10G 的叙事表示冲突。先确认它们是否改接 H 菜单、如何表现 3G 零钱及任务奖励，再同步正式工程和任务数据，不改币面额凑结果。
- F09 任务按明确用途和允许出售的任务实例校验，核对一次使用量与整份金额；不将 200G 同时作为销售收入和主线奖励。对 `day1_griffin_blood` 等剧情专用 ID 与普通定义映射逐项核对，不能只保护 Excel 对应的一个目录项。
- Day 2 招待需按次数扣 F06/F10 各 1 次并保留余量；当前任务 `items` 是整份语义，后续应增加显式按次需求或等效公开事务，不将整份扣除后手动退料。多耗单位和剧情事实另行确认。

## 独立战斗采购与携带

建议新增独立战斗原料 Resource 与 `CombatLoadout` 业务组件。静态商品保存稳定 ID、`combat_tier`、固定价和效果参数引用；运行快照保存杯 ID、槽位配置和携带状态。最多四杯、每杯最多三槽，在服务提交层检查，允许不满配。

购买整杯配置时，从战斗目录求每个已用槽的固定价之和，原子校验余额、携带上限、全部原料引用和请求回执，再一次扣钱并入库。采用“买原料再组杯”时采购和装配必须分成明确动作，已购买原料在装配时不能再收费；两种流程由产品选择一种后实现，不同时隐式存在。

先以独立数据验收 20/50/100G、混配 170G 和四杯全 T1 的 240G；空杯能否装备、替换/拆解退款、投掷耗杯、独立原料到效果执行器的映射需补齐，不能把现有经营投掷杯直接认作已完成战斗系统。经济报价不修改伤害、感知或区域效果。

## 存档迁移与失败边界

当前整局 v8、库存 v6、经济 v3。两分支曾复用旧版本号但字段结构不同，因此统一递增并按字段识别旧格式，保留既有 v2–v7 迁移链。经济与经营内的共享库存必须一致，价格、奖励与杯记录交叉校验后才整体恢复。新游戏清空账本和奖励，普通进出场景不清空。

旧图鉴只保存配方/发现日，没有随机加价或固定售价。建议将迁移记录标为 `legacy_unpriced`，迁移读取阶段不随机、不补发奖励；旧杯可查看，出售或重做前显式完成一次新规则定价。非法的旧纯人类自由杯、带冰块槽历史杯、F09 历史异常杯保留为只读历史资料，不强改成 H01–H06，不进入新普通销售或重做；合法哥布林历史杯经确认后仍沿用其稳定库存 ID。UI 需解释该状态，不能继续默用 20G。

如果上线前产品要求保留旧杯 20G，应改用显式旧价版本并补充库存/批次区分；当前快照未保存历史实际价，不能从存档准确反推出旧爆品专属售价。不要在迁移里伪造已抽取的逐槽加价。

新快照拒绝：重复规范配方键、缺失或错位槽、越界/非整数加价、槽价总价不一致、非法用途、无对应配置的奖励/战斗项和双方库存不一致。按 `pricing_version` 验证历史价格；平衡配置更新不得自动重抽已定价配方，旧版本规则需保留可验证数据。损坏包整体拒绝，原会话保持不变。

## 实施进度（2026-10-19，第一批：经济基础）

阶段 1 的主体已实现并通过模块验证（`tests/verify_economy_pricing.gd` 109 项；钱包 146 项、自由配方 207 项、GameState 126 项通过）：

- 22 行原料全部导入 `economy_tier`/`economy_scope`（F05 与 W02、F06 与 W04 共用同一条目，`source_ids` 记录双源）；F09 为 T5 + quest，`market_price = -1`。
- 新增静态 `EconomyRules`（档位标准价、单槽成本、加价区间、人类杯 3G、首发奖 150G、金币面额 10G、`pricing_version`）与纯函数 `FormulaPricing`（规范化槽位、区间、确认报价、记录复验）；RNG 只在首次确认时由 `GameState.confirm_formula` 注入，账本保存实际报价。
- 固定菜单 H01–H06 `sell_price = 3`；教学款与剧情成品不设固定价，其任务必须显式写 `rewards.money`（缺省为 0G 收入，不再回落 `ordinary_price`）；quest 成品禁止普通出售。
- 增补 `commit_story_transaction` 与 `prepare_exchange`：直接按次取得／扣除、货币付款／赠款和事实／专款变量原子提交，不通过整份补扣。固定菜单制作经 `commit_fixed_craft` 同步提交按次扣料、成品和制作队列。
- 原子制作 `GameState.commit_formula_craft`：按次扣料、成品入库、图鉴、回执、首发奖一次提交，失败整体不变；重复制作沿用首次发现的原始顺序与名称（`first_discovery`）。
- 快照版本：整局 v6、库存 v4、经济 v2；旧 `strange_coin` 按 10G 面额一次性折算进钱包；旧自由杯标记 `legacy_unpriced` 只读展示；v1/v2 严格键数校验防止擦除已记录用量。
- Day 1 人类原料 C01–C10 初始各 5 份，`day1_menu.tres` 提供 10 个 0G 整份补给商品（`supply_*`），复用 `WalletTransactions.purchase()`。
- 不安全阶段门控：`Day1Access.pricing_blocked`（day1.s05 夜间潜入）使 `confirm_formula` 返回 `unsafe_phase`；预览保持只读可用。

后续整合已完成正式 H01／3G、50G 潜入经费、酒馆 60／48G、按次交付和冷启动恢复。独立战斗采购与携带不在本期范围；正式爆品表保持为空。

## 影响方案的 Godot 4.7 文档

- [RandomNumberGenerator.randi_range](https://docs.godotengine.org/en/4.7/classes/class_randomnumbergenerator.html#class-randomnumbergenerator-method-randi-range) 的上下限均包含，符合整数加价；底层算法不是稳定契约，所以存实际报价，不只存 seed。
- [Resource 的缓存与共享引用](https://docs.godotengine.org/en/4.7/classes/class_resource.html#description)：同路径加载会返回缓存引用，运行中报价与领奖状态应存会话快照，不写回共享静态规则 Resource。
