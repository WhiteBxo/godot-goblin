# 携杯与交杯已回退，只保留采集结果行（2026-10-20）

同一天的两次尝试，结论分开记：**“把杯子拿在手上、再抛给顾客”不适合这款游戏**，已整体撤掉；**采集结果从浮层改成布局行**留下来。

## 为什么撤掉持杯与交杯

游戏是俯视 45° 的像素 2D，角色没有“端杯”“递出”的帧，也没有对应动画。做法只能是把产品图标贴到角色精灵旁边再补一段位移，结果是：

- 杯子像贴在围裙或胸口上，读不出“手在拿”；
- 走路时图标跟着起伏，和角色自身的步频对不上，看起来像抖动；
- 交付时图标自己飞过去，顾客没有任何接的动作，反而比“杯子直接入账”更出戏。

这类反馈在 2D 里必须由**角色动画帧**承载，图标替身做不到。已回退的部分：

- `main.gd`：`_carry_cup` / `_settle_carried_cup` / `_set_carried_art` / `_carried_cup_stock` / `_present_handover` / `_present_counter_payout` / `_hand_position` 全部删除，三种制作入口与两处交付恢复为“提交 + 文案 + 音效”。
- `HeldItemVisual` 与 `shop_player.tscn` 回到 `746814b3` 的状态：潜入用的火把/硬币仍按原样绘制，手部锚点回到 `y = -52`，没有额外的产品图与起伏。
- `UIFlourish` 删掉 `world_toss` / `world_pop` / `world_message` 及配套的世界层工具函数：没有使用者就不留死代码。

后续若真要表现“取杯—递杯”，前提是补齐角色动画帧（端杯行走、递出、接收），再回到这条线；纯图标方案不再考虑。

## 保留下来的：采集结果行

采集成功后，`ShopUI.show_harvest_result()` 在标题与正文之间插入一行 `获得 [材料图标] ×N` 的真实布局行，采集文案用 `settle()` 落定。

它最初也是浮层（材料图标从正文旁升起），会压到正文甚至订单笺上——弹窗里不该用浮层报告结果。改成布局节点后只会把正文往下推，任何状态下都不会盖住文字；订单板占用页面时这一行强制隐藏。
