# 奶茶系统手感打磨（2026-10-19）

本轮只补“按下之后发生了什么”的展示层节拍，不改制作规则、库存、订单结算和存档：`TeaProduction` 只多了一句更准确的空选择提示，`TeaMaking` 只多了一个只读的 `get_progress()`。

## 问题

制作是一次同步提交：点按钮 → 库存变化 → 一行文字出现。玩家感知不到“一杯做好了”，失败也只有红字；接单后订单笺的正文直接跳成另一张，泡茶三步没有节拍。

## 改动

| 时刻 | 之前 | 现在 |
| --- | --- | --- |
| 选择配方 | 预览行直接改写 | 预览行 `settle` 轻轻落下 |
| 加一份原料 | 材料托盘整块重建 | 新增的那一行单独弹一下（`_pop_chip`） |
| 批量杯数 | 数字和按钮文字变了 | 未达到上限时制作按钮跟着弹一次，提示“这一次会做几杯” |
| 制作成功 | 底部一行结果文字 | 成品杯从按钮左下角升起 3 杯（超过 3 杯只叠 3 个，数量由文案给出），结果文字 0.94 → 1 落下 |
| 制作被拒 | 红字出现 | 结果文字回缩 + 暖色一闪（`refuse`），失败仍只播一次 `ui.failure` |
| 按单制作 | 只弹一次成品图 | 状态戳“制作完成 · 已入库”斜着盖下来，同时从“立即交付”按钮侧升起成品杯 |
| 换一张订单 | 正文瞬间替换 | 整张笺 0.14s 淡入；同一张单的状态变化（可接取 → 进行中、缺料 → 可交付）改为戳一下状态行 |
| 交付/接单提示 | 出现与消失都是硬切 | 0.14s 淡入 + 卡片弹入，3s 后 0.32s 淡出 |
| 泡茶三步 | 文字从 0/3 变成 1/3 | 正确一步状态行弹一下，顺序错了回缩 + 暖色一闪（错误文案仍由调用方覆盖） |

新增 `src/UI/components/ui_flourish.gd`（`UIFlourish`）收纳这些一次性动作：

- `settle(control, from)`：数值落地，`TRANS_BACK` 收尾。
- `stamp(control)`：状态改判，从倾斜 1.28 倍回正。
- `refuse(control)`：操作被拒，一次回缩 + 暖色。
- `cups(anchor, icon, count, from)`：产出物离开台面。浮层挂到最近的**非 Container** 祖先上，绝不参与容器布局，不吃鼠标，一颗一颗升起后自毁（约 0.5s）。

`_prepare()` 每次先杀掉同控件的上一段动效、把 `scale/rotation/pivot` 复位，所以同一按钮连续点击不会累积变形。所有动作只碰 `scale`、`rotation`、`modulate`，不碰 `position/size`（容器会重排），也不碰焦点与信号。

调用点：`crafting_panel.gd`（已知配方）、`free_crafting_panel.gd`（自由调配）、`order_ticket.gd`（订单笺，板与制作台共用）、`shop_page.gd`（泡茶步骤）、`shop_ui.gd`（非模态提示）。

## 试玩

1. F5 进店，走到柜台接一张单，再走到制作台按 E：点“制作 1 杯并入库”，看杯从按钮左侧升起、状态戳盖下、按钮变成“立即交付”。
2. 切到“已知配方”，点一份配方，连点“最大”，看按钮文字和弹动；再清空选择后按制作，看结果行回缩。
3. 切到“自由实验”，选好基底后制作一杯，确认同样有升杯与落地。
4. 回到柜台“今日订单”用方向键换单，看订单笺淡入；接单后看状态行戳一下。
5. 交付给 NPC，看底部提示条的淡入淡出与钱包浮字。
6. 若进入泡茶教学（红茶 → 牛奶 → 珍珠），故意先点牛奶，看状态行回缩。
