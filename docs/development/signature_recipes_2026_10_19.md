# 新版十款爆品接入记录

用户确认“添加，以新的为准”后，将[爆品表](../design/signature_recipes_revised.md)的 S01–S10 导入共享 RecipeRules。源码原件保持不变，导入器通过两个菜单的 C/F 来源编号解析运行时 ID。当前玩法与试玩入口见[自由调配](../gameplay/free_tea_recipes.md#新版爆品试玩)。

命中爆品时专属售价、冰状态、名称、图鉴原文及三组标签按新表执行。普通报价账本保留，已有相同原料成品在满足资格和冰状态时按新表显示及结算；反向冰状态继续使用普通报价。发现奖励按 S ID 防重。五款有流程的配方通过原文手记调查解锁，另五款空白流程暂按首次正确试做发现。没有扩写对白或完整分镜。

S06 第二天市场直接买菇或雇佣跑腿当晚返回，救治消耗一次用量，之后读取市场提示解锁；第三天无法补开救治资格。旧第三天返回存档继续有效，但不能追溯满足新时限。S08 同时检查赌场实际领奖与 F11 发现事实。整局／库存／经济 schema 继续为 8／6／3。

## 实际验证

引擎为 Godot 4.7.2。API 使用核对 [Resource 官方文档](https://docs.godotengine.org/en/4.7/classes/class_resource.html)，共享资源深拷贝与现有场景、信号生命周期保持一致。

- `tools/milk_tea/import_signature_recipes.py --check`：十款与来源一致。
- `verify_signature_recipes.gd`：185 项通过，覆盖配方、价格、冰状态、奖励防重、试做门控、零库存发现、溢出回滚、存档恢复、截止日期和实际订单收入。
- `verify_signature_interaction.gd`：24 项通过，覆盖四个真实宿主的 E 键选中、调查关闭后解锁，及市场购买、胖哥布林救治的实际菜单按钮。已渲染四处阅读界面并检查；截图留在忽略目录 `.godot/`。
- 统一运行器筛选 `signature|free_recipes|day2_procurement|rpg_chapter_maps`：5/5 脚本通过。随后增加市场与救治按钮检查，交互脚本单独复跑通过。修复了两处新增调查点的不可达格子，并更新旧测试的第三天返回、爆品无专属价与空表假设。
- `verify_economy_pricing.gd`：136 项通过；完整回归中的公共状态、制作、订单交付和保存边界测试通过。
- `git diff --check`：通过；修改文档的相对文件链接已核对。

完整回归执行 `python tests/run_all.py --godot <4.7.2引擎>`，首次 101 项结果为 65 PASS、28 FAIL、1 CRASH、6 SKIP、1 HANG。修复并复跑本次相关的三个失败脚本后，未再执行整个套件。
