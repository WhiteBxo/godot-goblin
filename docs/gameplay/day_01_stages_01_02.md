# Day 1 前两阶段正式流程

F5 从标题菜单选择“新游戏”（或打开 src/core/main.tscn 后 F6）进入奶茶店，自动演出与玩家操作交替。对白使用 E / 空格 / Enter 推进，WASD / 方向键移动，靠近交互点按 E，Esc 关闭弹窗，P / Esc 使用现有暂停界面。

## 试玩验收

1. 开场独白结束，人类顾客从门口走到柜台。去收银台按 E 打开订单板，选择订单并点击“接取订单”；制作台按 E 后默认带入红茶、奶精、珍珠和糖浆，确认制作一杯并入库。
2. 关闭制作界面，回到柜台靠近人类顾客按 E 交付。玩家在柜台内即可交付，交互范围向柜台内延伸。成品扣除、任务完成、收入 10 同时提交；交付短反馈后按原 Bridge 屏障继续剧情。
3. 第一位哥布林点单后，再到收银台接取，按订单制作茉莉绿茶、奶精、椰果和糖浆，交付后古怪金币增加 1，随后观看古怪金币反应与三位哥布林入店闲聊。
4. 解锁提示后，可打开异世界见闻录，查看赌场、格里芬之血、长老三个空白条目。没有提前编写解释；未读状态沿用原服务。
5. 接取三笔群体订单，可自由安排制作和交付顺序。甲乙丙分别需要红茶/奶精/不加小料、红茶/奶精/珍珠、茉莉绿茶/奶精/椰果；每杯还消耗糖浆 1 份，每次交付获得古怪金币 1 枚。
6. 三单全部成功结算，且无暂停 / 模态阻挡后播放前两阶段结尾。总制作和交付各 5 杯，钱包净增 10，古怪金币共 4 枚，仍为 Day 1，停在准备调查古怪金币价值的状态。

古怪金币可在仓库「全部」或「剧情物品」查看，不作为食材，S01–S02 不提供消费或出售入口。没有本地自动存档及继续游戏菜单。原稿指定的结尾坏笑立绘已接入；尚未提供或未确认复用的表情沿用默认显示。人类顾客使用红衣男顾客动画，哥布林使用普通哥布林动画；没有新增趴柜台或翻硬币专用动画。

2026-10-18 补充：S01–S02 仍不提供 G 消费/出售入口；后续[潜入投掷组件](day_01_stealth.md)支持在正式配置齐备后，每次真实投出消费一枚 strange_coin，不与普通钱包兑换。当前 S05 正式配置仍受 P06/P08/P09 阻塞；基础 pay_items 原子扣物品能力已具备，正式支付数据尚未发布。

## 装配与状态边界

- main.tscn 保存 day1_story_enabled=true；聚落从正式会话进入时根据 profile=day1 延续剧情模式，新进程直接 F6 聚落仍为 tutorial。Systems 下的 Day1ShopController 注入注册、加载数据、请求首次事件，并按配置恢复检查点；事件顺序由 Story v1 与 Bridge v2 JSON 控制。营业余额与续播按钮由 UI 模块的 Day1BusinessHUD 展示，宿主只连接公开接口。
- 前两阶段已迁移，以 docs/story_authoring/day1_stages_01_02_project.json 为演出、对白和 Bridge phase 来源；原稿 docs/design/day_01_stages_01_02_draft.md 保留为初稿。Dialogue、Story、phases 和 setup 数据在 src/resources 下，Beat 映射与工程 SHA-256 在 docs/story_authoring/day1_stages_01_02_bridge.json。F3 编辑和预览见[游戏内编排](../guides/story_editor.md)。setup、订单和交付业务仍独立维护。
- 门口、通道、柜台和三人站位保存在关卡 StoryPositions 中。Actor 预置并按剧情显隐，隐藏或未接单的人物不提供交付入口。可见 NPC 脚底占据层 3，阻挡玩家；隐藏时退出实体层。NPC 自身仍受地图墙体限制。店内角色与家具按脚下位置和家具基线共同排序，同一家具区间的角色使用 Y 排序；玩家在柜台后、顾客在柜台前时分别保持正确遮挡，房间屋顶仍在角色之上。
- GameState 持有唯一库存、钱包和制作服务。select_business_profile("day1") 仅允许从无进度会话选择；相同配置重入是幂等的。旧三单配置为 tutorial；原 Demo 与组件测试使用 src/debug/story/legacy_shop.tscn 明确关闭正式剧情。
- TeaProduction 使用会话选定的菜单及 accepted_flag；查看订单板只写 shop.orders_viewed，显式接取再写对应 accepted_flag。正式订单不依赖静态三单队列；制作只生成成品和制作进度，交付才产生收入与剧情完成事实。
- TaskCatalog.rewards.money 为可选非负整数，delivery.accepted_flag 为可选接单标记，旧任务字段继续有效。TaskDelivery 的原交付接口不变；正式会话调用 GameState.commit_delivery，由钱包准备完整草稿，再在会话锁内静默提交，最后发布完整结果。旧组件独立库存的物品交付保持兼容。
- 群体完成由 setup 的订单批次配置聚合三个交付回执。Bridge 不处理制作规则或经济，不在 Director busy 中开放玩法。
- 见闻录在 day1.chronicle_unlocked 前隐藏且公开打开接口拒绝；原有空白词条、未读与已读语义不变。
- 音频由正式宿主注册原资源。BGM 开场淡入并跨事件保持；打开订单、接取、制作和交付经 InteractionAudio 播放实际结果音；当前制作成功配置为 shop.sealer。BGM 与通用交互音效的现行配置见[音效库](../assets/sound_library.md)。

## 快照与中断

当前完整快照为 v4，business.profile_id 与库存、制作、钱包、回执和剧情在同一包中；库存子快照为 v3，含自由配方杯、图鉴与按次使用记录。旧完整 v2/v3 支持迁移，v2 以 tutorial 配置并为古怪金币补零；只有剧情的 v1、局部或损坏快照仍整体拒绝。详见[统一经营会话](business_session.md#快照边界)。场景切换或重载不切换经营配置，新游戏重置当前所选配置。

三个玩法边界与最终完成状态都可恢复。人物位置和显隐由最近已完成事件的检查点投影；未完成演出从本段起点恢复，已完成演出不重播。不保存逐帧镜头或动画位置。取消/失败后显示「继续剧情」，由玩家显式恢复；结算有独立稳定回执，不随演出重试重复发放。
