# 饮品投掷与区域效果（第三期）

第三期接入[自由配方](free_tea_recipes.md)生成的 `throw` 参数，复用 [Day 1 潜入服务](day_01_stealth.md)、玩家投掷动作和共享杯库存。正式聚落的潜入配置仍缺确认绑定，保持 `PENDING`；本期没有补写地图、火把来源、支付、醉酒事件或撤离剧情。

## 使用与消费

潜入 HUD 的饮品下拉框列出持有的配方杯及数量。选择后，鼠标指向落点，按 `player_throw`（默认 F）。开始动作时固定杯 ID、落点与参数副本；动画释放时通过 `WarehouseInventory.try_consume_drink(id, quantity = 1)` 扣一杯。古怪硬币、火把仍使用原有整件物品消费接口。

提前取消不扣杯，释放后取消或重试不退款。释放时库存不足、会话正在整体更新，均不生成投掷物；同步通知重入也不会重复释放。出售与投掷使用同一份 `drinks` 库存。投完最后一杯仍保留图鉴记录，不消耗原料、钱包或额外冰块。

加冰仍只是独立命名选项，不占原料槽、不扣冰块、不授予地雷能力。原料表保留的 `ice → mine` 只用于历史原料配方兼容与执行器验证，新配方不能选择冰块原料。

## 区域与守卫

`DrinkEffectArea` 属于场景内 EffectRoot，由服务的物理 tick 推进，不另开 Timer 或 Autoload。基础区域是以落点为中心、边长 `area_cells × cell` 的正方形；当前一格 64 像素、基础持续 3 秒，扩散后最多 9×9 格，持续上限 30 秒。数值从 `throw_tuning.tres` 经配方参数传入，执行器不另维护一份平衡表。

| 效果 | 当前行为与同原料叠层 |
| --- | --- |
| 引诱 | 按 `pulse_seconds` 在落点产生硬币分心；当前每秒一次。脉冲边长每份 3 格，受面积上限约束，扩散可继续扩大。重复原料也延长单次分心时间，间隔保持不变 |
| 灼烧 | 区域内守卫进入既有混乱；点燃配置中已确认的可燃目标，保留其燃烧和附近混乱参数。区域混乱时长乘层数并受持续上限约束 |
| 致幻 | 进入既有 `CONFUSED` 状态，时长乘层数。保留醉酒守卫的既有混乱免疫 |
| 麻痹 | 新增 `STUNNED`：有效视距为 0，警戒清零，不转身、不发现或报警。分心、混乱不能覆盖眩晕；持续时长乘层数 |
| 腐蚀 | 发现玩家的积累速度降低。当前倍率为 `3 × 层数`，一层需原来 3 倍时间、两层需 6 倍；对显式可腐蚀目标按每秒伤害乘层数 |
| 毒气 | Day 1 按守卫移动速度向区域外驱离，速度乘层数；眩晕优先，不能自行移动。暂不引入生命值或掉血 |

持续接触刷新状态，不会每帧把同一层数再次累加。腐蚀与眩晕独立计时；已放行、隐藏或正被演出接管的守卫不接收区域效果。眩晕醉酒守卫也不生成放行、支付或事件完成事实，撤离仍需既有业务条件。

| 修饰 | 当前行为 |
| --- | --- |
| 扩散 / 击退 | 每份增加 4 格边长；区域内守卫按每份 2 格击退，每杯对每个守卫只位移一次 |
| 粘留 | 每份增加 10 秒，受持续上限约束 |
| 聚拢 | 把区域内守卫向落点拉近，每份最多 5 格，抵达中心即停止；每杯每个守卫一次 |
| 附着 / 传染 | 区域首次触及守卫后跟随该守卫，边长至少每份 3 格，持续至少每份 8 秒并受上限约束；沿途守卫也可受影响，不递归复制新区域 |
| 地雷 | 等待守卫进入每份 1 格的触发范围，或等待 3 秒后激活。等待不消耗生效时长，触发范围受面积上限约束 |
| 静音 / 穿墙 | 抑制落地的普通硬币分心，飞行与区域射线忽略世界阻挡；布尔参数不按层数倍乘。引诱仍按自身间隔主动触发 |

普通投掷物通过扫射世界层防止高速穿墙，普通区域对目标也校验世界遮挡。`PlayerController.displace_by()` 使用 `move_and_collide()` 做实际位移，不争夺演出控制、不修改朝向；即使效果能穿墙，守卫实体的聚拢、击退、驱离也不能穿过实体墙。毒气遇墙可被挡住，本期没有增加绕墙寻路。

## 可腐蚀物绑定

`Day1DestructibleTarget` 是独立 `Area2D` 组件，必须显式配置 `target_id`、`design_reference`、有效碰撞形状、耐久和 `blocker: CollisionObject2D`；可选 `visual: CanvasItem`。通过 `Day1StealthSetup.destructible_targets` 注入服务。不能根据物体名字自动推定木门、箱子或木制材质。

腐蚀累计到耐久后，移除绑定阻挡的碰撞层并隐藏绑定外观；不删除节点、不自动发奖励。失败、重试、取消、reset/restore 和退出时恢复初始碰撞层、外观和耐久。当前正式地图尚未绑定此组件。

## 生命周期与撤离

模态、演出及外部操作锁暂停投掷物、区域和守卫计时，树暂停也停止物理推进。失败或醉酒拦截会清理区域、在途物、燃烧、状态与可腐蚀物；重试另恢复角色位置和朝向。会话替换及退出清理全部临时状态；飞行、区域、位移与损坏不写入存档，已扣杯数由既有库存快照保存。

`confusion_required` 现在同时接受本次投掷造成且仍有效的守卫混乱或可燃物燃烧；眩晕、旧尝试混乱、已经到期的混乱均不能替代。血液、支付和必然事件条件保持原契约。

## 验证与试玩

```sh
godot --headless --path . --script res://tests/verify_drink_throw.gd
godot --path . --rendering-method gl_compatibility --script res://tests/verify_drink_throw.gd -- --capture
```

F6 入口：`src/debug/stealth/drink_throw_demo.tscn`。这个 Debug 独立夹具准备测试火把、四个角色、可燃物、木箱与八种持有饮品，不给正式关卡注入占位内容。F6 会重置测试会话；它持有隔离的库存夹具，不代表正式关卡已经接通。

1. 下拉选择含两份薄荷糖浆的饮品，对入口守卫按 F：杯数减一，出现紫色区域和眩晕标记，守卫暂时不发现玩家。
2. 选择含草莓果酱的饮品，对棕色木箱投掷：腐蚀一段时间后箱子消失，可以穿过原来的实体阻挡。
3. 用普通杯和含幻金菇的杯分别朝灰墙后投掷：普通杯被墙截停，幻金菇杯到达指定落点，落地不额外引开入口卫。
4. 面向右侧仍在观察的守卫走入视野，等待失败后按“从检查点重试”：状态和木箱恢复，投出的杯不返还。

图形检查输出到 `.godot/drink_throw/demo.png`，使用真实动作、碰撞和 HUD；脚本驱动交互不等同人工完整通关。相关回归覆盖自由配方、原有潜入、玩家、库存、制作、交付、钱包、GameState、经营会话、宿主和 UI。没有运行不相关的全项目剧情回归或 Release 导出。

2026-10-18 验证结果：Godot 4.7.2 Compatibility 图形测试 102 项通过，已查看最终截图；16 个相关回归脚本通过，包括原潜入 84 项、自由配方 189 项、玩家动作 177 项和 UI 主题 186 项。编辑器最终导入无脚本解析错误，退出仍报告既有 MCP 插件的 495 个对象、10 个资源保留诊断，与本期首次导入一致。文档链接与 `git diff --check` 通过。

实现核对：[Godot 4.7 射线参数](https://docs.godotengine.org/en/4.7/classes/class_physicsrayqueryparameters2d.html)明确区域检测默认关闭，飞行显式开启以命中可燃组件；[PhysicsBody2D](https://docs.godotengine.org/en/4.7/classes/class_physicsbody2d.html)规定 `move_and_collide` 接受位移向量，因此连续驱离使用速度乘物理 delta，击退使用一次性距离。
